## 🔴 치명적

### [#1] ✅ Idempotency 키가 Alpaca에 전달되지 않음 (중복 주문)
- **파일:** `src/app/api/orders/route.ts`, `src/lib/order-schema.ts`
- **문제:** `clientOrderId`를 생성·audit 저장하지만 `alpaca.placeOrder()`에 `client_order_id`를 넘기지 않아, 직전 커밋의 idempotency 기능이 무력화. 네트워크 재시도/더블클릭 시 동일 주문이 두 번 체결될 수 있음. `OrderAudit.clientOrderId`에 `@unique`도 없어 DB 레벨 방지도 없음.
- **수정:** `placeOrder` 호출에 `client_order_id: body.clientOrderId` 추가. 테스트: `__tests__/app/api/orders/orders.test.ts` (forwards clientOrderId).
- **후속 권장:** `OrderAudit.clientOrderId`에 `@unique` 추가 + 중복 시 단락(short-circuit)으로 2차 방어.

### [#2] ✅ 세션이 영구 유효 (만료·위변조 검증 미흡)
- **파일:** `src/lib/session.ts`, `src/app/api/login/route.ts`
- **문제 1:** `verifySession`이 HMAC 서명만 확인하고 payload의 발급 시각을 검증하지 않아, 탈취된 토큰이 `SESSION_SECRET` 교체 전까지 무기한 유효.
- **문제 2:** 서명 비교 시 `Buffer.from(sig, 'hex')`가 첫 무효 문자에서 잘려, `token+'x'` 같은 변조 토큰이 통과(테스트로 확인됨).
- **수정:** `SESSION_MAX_AGE_MS`(30일) 도입, 발급 시각 파싱 후 만료/미래 토큰 거부, 서명은 고정 길이 hex 문자열로 비교. 로그인 쿠키 `maxAge`도 동일 상수와 동기화. 테스트: `__tests__/lib/session.test.ts`.

## 🟠 중요

### [#3] ✅ 자동적립(recurring) 주문 추적·중복방지 누락
- **파일:** `server.ts`, 신규 `src/lib/recurring-runner.ts`
- **문제:** 수동 주문과 달리 `client_order_id` 미전달(중복방지 없음), `OrderAudit` 미기록, `Lot` 미생성(적립 매수분이 포트폴리오/세금 계산에서 누락). 또한 `placeOrder` 성공 후 `lastRun` 갱신 실패 시 다음 tick에 재매수 위험.
- **수정:** 인라인 루프를 `runRecurringInvestments(now)`로 추출. 매수 시 `client_order_id` 전달, `OrderAudit` 기록, 체결 즉시 `Lot` 생성. `lastRun`을 주문 전 optimistic 갱신 후 실패 시 롤백 → 재매수 방지. 테스트: `__tests__/lib/recurring-runner.test.ts` (5건).

### [#4] ✅ 로그인 레이트리미터 신뢰성
- **파일:** `src/app/api/login/route.ts`, 신규 `src/lib/rate-limit.ts`
- **문제:** in-memory `attempts` Map이 정리되지 않고(누적), `x-forwarded-for`를 검증 없이 신뢰.
- **수정:** `createRateLimiter`(매 호출 만료 엔트리 sweep로 누수 차단) + `clientIp`(X-Forwarded-For의 leftmost=실제 클라이언트 사용)로 교체. 테스트: `__tests__/lib/rate-limit.test.ts` (6건).
- **후속 권장:** 다중 인스턴스 운영 시 공유 저장소(Redis 등)로. 신뢰 프록시 환경에서만 X-Forwarded-For 신뢰.
