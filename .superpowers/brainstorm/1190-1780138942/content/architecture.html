아키텍처 접근 방식 선택

기술 스택 + 구조 — 하나를 골라주세요

A

Next.js Fullstack (추천)

Frontend: Next.js (React) + TypeScript
Backend: Next.js API Routes (BFF)
실시간: WebSocket (brokerage 직연결)
봇 연동: Bot가 REST로 상태 푸시 → API Route로 수신

장점

  • 하나의 프로젝트로 프론트+백 관리
  • API 키 서버에서 안전하게 보관
  • TypeScript 풀스택
  • 배포 간단 (Vercel 1줄)

단점

  • WebSocket 유지에 서버리스 한계 (셀프호스팅 권장)
B

React (Vite) + FastAPI

Frontend: React + TypeScript (Vite)
Backend: Python FastAPI
실시간: FastAPI WebSocket
봇 연동: 같은 Python 생태계라 봇 코드 직접 import 가능

장점

  • 봇(Python)과 백엔드가 같은 언어 → 코드 공유 쉬움
  • FastAPI 성능 우수, WebSocket 네이티브 지원
  • 나중에 봇 기능 통합하기 편함

단점

  • 프론트/백 두 개 프로젝트 관리
  • 배포 설정 복잡도 증가
C

React (Vite) + Node.js/Express

Frontend: React + TypeScript (Vite)
Backend: Node.js + Express + Socket.io
실시간: Socket.io (안정적인 WebSocket 래퍼)
봇 연동: Bot → HTTP/WS → Express → Frontend

장점

  • Socket.io로 실시간 구현이 가장 편함
  • JavaScript 풀스택
  • 레퍼런스 많음

단점

  • 프론트/백 두 개 프로젝트 관리
  • 봇(Python)과 언어 분리
